# P2-019: OpenCode Go最新モデルカタログ追従

## 概要

利用可能なモデル一覧を OpenCode Go の最新の公式Endpoints表に追従させる。P2-011 の後継として、公式表の変更差分を定期的に取り込み、実API疎通を確認する。

## 背景

- P2-011 で26モデル対応・live test 26/26成功まで到達したが、公式表は随時更新される
- P2-015 で27件化（`muse-spark-1.3-contributor`追加）、P2-016 で grok-4.6 残件など、カタログは継続的な追従が必要
- P1-012（Agent一本化）後のモデルカタログの扱いは P1-012 の方針に従う

## 方針（確定事項）

- **正**: [OpenCode Go公式Endpoints表](https://opencode.ai/docs/go/)
- **方式**: P2-011 と同型（カタログ更新＋3プロトコル使い分け＋live test）
- **前提**: P2-011（対応中）の完了をベースにする

## 検討項目

- [ ] 公式Endpoints表の最新差分確認（追加・廃止モデル）
- [ ] `modelCatalog.ts` への反映とプロトコル分類（Responses / Chat Completions / Messages）
- [ ] P2-011 同型の live test（`npm run test:live:models`）での全モデル疎通
- [ ] 利用不可モデルの扱い（既存会話は閲覧可・再選択まで送信不可。P2-011条件5と同型）
- [ ] P1-012 との整合（廃止範囲にモデル一覧APIが含まれる場合は本件の適用先を見直す）

## 受け入れ条件

（詳細は [spec](../../P2-019/spec.md)・[plan](../../P2-019/plan.md) を参照）

1. `GET /api/models` が最新の公式Endpoints表と一致する
2. 各モデルが正しい上流プロトコルへ送信される
3. live test で全モデルの実APIチャットが成功する（P2-011条件6と同型）
4. APIキー・リクエスト本文・回答本文・上流エラー本文をログへ出力しない（P2-011条件7と同型）
5. 利用不可モデルを保持する既存会話の扱いが P2-011 と一致する

## 関連ファイル

- `frontend/src/`（モデル選択UI。P1-012の廃止範囲と連携）
