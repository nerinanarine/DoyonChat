# P2-018: Agent gateway ContainerAppのスケールゼロ化＋起動中ローディング

## 概要

Azure料金削減のため、agent gateway の ContainerApp の常時起動インスタンスをゼロ（`minReplicas: 0`）にする。コールドスタートの待ち時間は許容する代わりに、コンテナ起動中であることをユーザーに伝えるローディング画面を表示する。

## 背景

- 現状 `minReplicas: 1` で常時課金が発生している（`infra/modules/agentPool.bicep`）
- Agent利用は間欠的で、常時起動のコスパが悪い
- 起動待ち自体は我慢できるが、何も表示されないと故障に見える

## 方針（確定事項）

- **対象**: agent gateway の ContainerApp のみ（Functions / SWA は対象外）
- **設定**: `minReplicas: 0`（`maxReplicas` 等の現行スケール設定は維持）
- **UX**: コンテナ起動待ち中はローディング画面を表示し、起動中であることを明示する
- **環境**: dev先行で検証後にprodへ適用

## 検討項目

- [ ] `agentPool.bicep` の `minReplicas` を 0 に変更した場合の影響（デプロイ・CI・ヘルスチェック）
- [ ] 起動待ちの検出方式（gateway疎通ポーリング vs エージェントセッション開始APIの応答待ち）
- [ ] ローディング画面の設計（P2-013のloadingパターンと同型検討・タイムアウト表示・再試行導線）
- [ ] コールドスタート時間の実測（devで計測し、許容範囲か確認）
- [ ] dev/prodの適用順序と切戻し手順

## 受け入れ条件

1. agent gateway の ContainerApp が `minReplicas: 0` で動作する
2. アイドル時にインスタンスがゼロまでスケールダウンし、課金が削減される
3. コンテナ起動中はローディング画面が表示され、ユーザーが起動待ちと認識できる
4. 起動完了後は通常どおりエージェントが利用できる
5. 通常チャット・既存の承認フローに回帰がない（P1-012実施後はAgentモードのみで確認）

## 関連ファイル

- `infra/modules/agentPool.bicep`（`minReplicas`）
- `infra/main.json`（生成物・要再生成確認）
- `frontend/src/`（起動中ローディングUI）
- `functions/src/`（起動待ち検出・中継があれば）
- `agent/`（ヘルスチェック・起動時間）
