# P3-016: ユーザー専用Azure Filesマウント・アーティファクト保存

## 概要

ユーザーごとに ContainerApp（agent gateway）へ専用の Azure Files ボリュームをマウントし、エージェントが作成したアーティファクトを保存・永続化できるようにする。

## 背景

- P3-015 でエージェントのファイル作成・読み取りを進めているが、保存先がコンテナ内の使い捨て領域だと再起動で消える
- 作成物をユーザー単位で永続化し、後から参照・ダウンロードできる必要がある
- ユーザー間の分離（他ユーザーの成果物が見えないこと）が必須

## 方針（確定事項）

- **対象**: agent gateway の ContainerApp へのマウント（P3-015 の保存先として利用）
- **分離**: ユーザーごとに専用領域（他ユーザーから不可視）
- **容量・保持期間・アクセス範囲**: 後で決定（本件では方式確定とdev実証を優先）
- **環境**: dev先行

## 検討項目

- [ ] マウント方式（Azure Files ボリューム vs SMBマウント・ContainerAppボリューム方式の選定）
- [ ] ユーザー分離の実現方式（ユーザー別共有/ディレクトリ・サブディレクトリ・ACL）
- [ ] プロビジョニング方式（初回利用時自動作成 vs 事前作成・IaC管理）
- [ ] 容量・クォータ・保持期間・削除ライフサイクル（後で決定）
- [ ] P3-015 の作業ディレクトリ・ダウンロード導線との接続（保存先パスの設計）
- [ ] Key Vault・マネージドID等の認証方式（キー直書き禁止）
- [ ] コスト試算（Files容量・トランザクション）

## 受け入れ条件

1. ユーザーごとに専用の永続領域がマウントされ、エージェントが作成物を保存できる
2. 他ユーザーの領域は参照・一覧できない
3. コンテナ再起動後も作成物が残存する
4. チャット画面から保存物のダウンロードができる（P3-015の導線と接続）
5. シークレットの安全な管理（キー直書きなし）ができている

## 関連ファイル

- `agent/`（作業ディレクトリ・保存パス）
- `functions/src/`（ダウンロード配信・所有者検証）
- `frontend/src/`（ダウンロード UI）
- `specs/P3-010/`（sessions方式の参照）
