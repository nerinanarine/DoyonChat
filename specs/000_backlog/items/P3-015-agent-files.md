# P3-015: エージェントのファイル作成・読み取り（pi-subagents 前提）

## 概要

エージェントにファイル作成・読み取り機能を提供する。実行は P3-014 で整備する `pi-subagents` 基盤のサブエージェントを前提とする。作成物はチャット画面からダウンロードできる。本件はファイル機能のみに縮小し、pi-subagents 基盤の組み込みは P3-014 に含める（Q11）。

## 背景

- P3-010 の gateway は `--no-tools` 起動で、ファイル操作手段がない
- ドキュメント作成（Office→PDF 等）をエージェントに委譲したい

## 方針（確定事項）

- **実行主体**: `pi-subagents` 配下（サブエージェントが作業を担当）
- **対象形式**: docx / xlsx / pptx / pdf ＋ テキスト・画像（Q6）
- **受け渡し**: チャット画面からのダウンロード（Q7）
- **環境**: dev先行（P3-014 と同様）
- **前提**: P3-010（gateway が存在すること）

## 検討項目

- [ ] ~~`pi-subagents` の gateway 組み込み実機検証（P3-010 の既知残件。先行課題）~~ → P3-014 で実施。本件は基盤完成を前提とする
- [ ] ファイル操作ツールの方式
- [ ] ファイル操作ツールの方式：piネイティブ read/write/edit の有効化 vs 形式別専用ツール（create_docx 等）の拡張化。承認・監査の面では専用ツール化が安全
- [ ] 生成ライブラリの選定・コンテナ同梱（docx / exceljs / pptxgenjs / pdf-lib 等）
- [ ] 作業ディレクトリの設計（会話単位の分離・ライフサイクル。P3-010 の sessions 方式と同型検討）
- [ ] ダウンロード導線の設計（Functions 経由の配信・認証・所有者検証。P3-010 の F1 方式と同型検討）
- [ ] 作成系ツールの承認分類（Q4 は読み取りのみ auto。作成系は dangerous-only を推奨。別途確定）
- [ ] 読み取り対象の範囲制限（プロンプトインジェクション緩和。P3-010 と同型の配慮）

## 受け入れ条件

1. dev 環境のエージェントが docx / xlsx / pptx / pdf / テキスト / 画像の読み取りができる
2. dev 環境のエージェントが docx / xlsx / pptx / pdf ファイルを作成できる
3. 作成物をチャット画面からダウンロードできる
4. 作成系ツールの承認分類が確定し、実装と一致している
5. 既存の承認フロー・通常チャットに回帰がない

## 関連ファイル

- `agent/`（拡張・allowlist・Dockerfile）
- `functions/src/`（ダウンロード配信・所有者検証）
- `frontend/src/`（ダウンロード UI）
- `specs/P3-010/`（sessions・F1 等の先行パターン参照）
