# Feature Specification: 会話の手動リネーム

**Feature Branch**: `[008-rename-conversation]`

**Created**: 2026-08-22

**Status**: Draft

**Input**: [P2-005 backlog item](../000_backlog/items/P2-005-rename-conversation.md)

> **現行構成に関する注記:** 現行バックエンドは Azure Functions (`functions/`) である。バックログに記載された旧Expressバックエンド (`backend/`) は既に削除済みのため、本機能はFunctionsのみを対象とする。

## User Scenarios & Testing

### User Story 1 - 会話一覧でタイトルを編集する (Priority: P2)

ユーザーはサイドバーの会話タイトルをその場で編集し、Enterキーで保存できる。リネーム対象が現在開いていない会話でも、会話を切り替えずにタイトルだけを編集できる。

**Why this priority**: 自動生成または初期作成されたタイトルを、会話の用途が分かる名前へユーザー自身で変更できるようにするため。

**Independent Test**: 会話一覧で任意のタイトルをクリックし、入力欄へ変更後、別の有効なタイトルを入力してEnterキーを押す。更新APIが1回だけ呼ばれ、一覧とアクティブ会話ヘッダーへ新しいタイトルが反映され、再読み込み後も維持されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 会話一覧が表示されている状態、**When** ユーザーが会話タイトルをクリックする、**Then** 現在のタイトルが入ったインライン入力欄へ切り替わり、入力欄へフォーカスされる
2. **Given** 非アクティブ会話を表示している状態、**When** ユーザーがそのタイトルをクリックする、**Then** アクティブ会話を切り替えずに対象タイトルだけが編集状態になる
3. **Given** 有効な新タイトルを入力した状態、**When** ユーザーがEnterキーを押す、**Then** 更新APIが1回だけ呼ばれ、成功レスポンスのタイトルが会話一覧へ反映される
4. **Given** アクティブ会話のリネームが成功した状態、**When** 画面を表示し続ける、**Then** サイドバーと会話ヘッダーの両方に新タイトルが表示される
5. **Given** リネームが成功した状態、**When** ユーザーがページを再読み込みする、**Then** 保存済みの新タイトルが表示される
6. **Given** リネーム保存中の状態、**When** ユーザーがEnterキーを繰り返し押す、**Then** 更新リクエストは重複送信されない

### User Story 2 - 編集を安全にキャンセルする (Priority: P2)

ユーザーは編集中の変更をEscキーまたはフォーカス移動で破棄できる。無効なタイトルは保存されず、既存タイトルが維持される。

**Why this priority**: 意図しない変更や空タイトルの保存を防ぎ、キーボードで予測可能に操作できるようにするため。

**Independent Test**: タイトルを変更してEscキーを押す場合、フォーカスを外す場合、空白のみでEnterキーを押す場合を個別に実行し、APIが呼ばれず元のタイトルが表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** タイトルを編集中の状態、**When** ユーザーがEscキーを押す、**Then** APIを呼ばずに編集を終了し、元のタイトルへ戻る
2. **Given** タイトルを編集中の状態、**When** 入力欄からフォーカスが外れる、**Then** APIを呼ばずに編集を終了し、元のタイトルへ戻る
3. **Given** 入力値が空または空白のみの状態、**When** ユーザーがEnterキーを押す、**Then** APIを呼ばずに編集を終了し、元のタイトルへ戻る
4. **Given** 日本語IMEで文字を変換中の状態、**When** 変換確定のEnterキーイベントが発生する、**Then** 保存処理は開始されず、編集状態が維持される
5. **Given** 100文字を超えるタイトルを入力した状態、**When** ユーザーが保存しようとする、**Then** APIを呼ばずに編集状態を維持し、入力エラーが表示される
6. **Given** ある会話のタイトルを編集中の状態、**When** 別の会話タイトルの編集を開始する、**Then** 最初の編集は保存されずキャンセルされ、同時に編集状態となる会話は1件だけになる

### User Story 3 - エラー時に入力を失わず再試行する (Priority: P2)

更新APIが失敗した場合、ユーザーは入力したタイトルを失わずに原因を確認し、修正または再試行できる。

**Why this priority**: 一時的な通信障害やサーバーエラーによって入力内容が消えることを防ぐため。

**Independent Test**: 更新APIを失敗させ、編集状態と入力値が維持され、インラインエラーが表示されることを確認する。その後APIを成功させ、同じ入力から保存できることを確認できる。

**Acceptance Scenarios**:

1. **Given** 有効なタイトルを入力した状態、**When** 更新APIが失敗する、**Then** 編集状態と入力値が維持され、対象会話の近くにインラインエラーが表示される
2. **Given** 更新失敗後の編集状態、**When** ユーザーが再度Enterキーを押してAPIが成功する、**Then** 新タイトルが反映され、エラー表示と編集状態が解除される
3. **Given** 更新失敗後の編集状態、**When** ユーザーがEscキーを押すかフォーカスを外す、**Then** エラーと入力値が破棄され、元のタイトルへ戻る

### User Story 4 - 所有する会話だけを更新する (Priority: P2)

認証済みユーザーは自分が所有する会話だけをリネームでき、他ユーザーの会話の存在や内容を取得できない。

**Why this priority**: P1-006で導入済みの会話所有権境界を、新しい更新APIでも維持するため。

**Independent Test**: 自分の会話IDと他ユーザーの会話IDで更新APIを呼び、自分の会話だけが更新され、他ユーザーの会話は404となることを確認できる。

**Acceptance Scenarios**:

1. **Given** 認証済みユーザーが所有する会話、**When** 有効なタイトルで更新APIを呼ぶ、**Then** タイトルが永続化され、更新済みConversationが返される
2. **Given** 存在しない会話または他ユーザーが所有する会話、**When** 更新APIを呼ぶ、**Then** どちらも404が返り、会話情報は開示されない
3. **Given** 認証に必要なユーザー識別子がない状態、**When** 更新APIを呼ぶ、**Then** 401が返り、データは変更されない

## Edge Cases

- **前後に空白があるタイトル**: 保存前に前後の空白を除去し、除去後の値をFrontendとFunctionsで検証・保存する
- **空または空白のみ**: 保存リクエストを送らず、元タイトルを維持する。APIへ直接送られた場合は400を返す
- **100文字超過**: Frontendでは送信せずインラインエラーを表示し、APIへ直接送られた場合は400を返す
- **同じタイトル**: 有効な入力として許可する。保存時は通常の更新APIを呼び、一覧順は変更しない
- **重複タイトル**: 複数会話が同じタイトルになることを許可する
- **日本語・絵文字**: 通常のUnicode文字列として保存・表示する
- **IME変換中のEnter**: `isComposing`中は保存キーとして扱わない
- **保存中の再操作**: 同一会話への二重送信を防ぐ
- **削除操作との競合**: タイトル操作と削除操作はイベント伝播を分離し、リネーム開始によって削除や会話切り替えが発生しない
- **API失敗**: 永続化前のローカルタイトルへ確定せず、入力と編集状態を維持する
- **Cosmos DB利用不可**: `COSMOSDB_REQUIRED=true`の現行方針に従い503を返す

## Requirements

### Functional Requirements

- **FR-001**: Frontendは会話タイトルをクリックまたはキーボード操作したとき、現在値入りのインライン入力欄を表示しなければならない
- **FR-002**: タイトル操作は会話行の選択イベントと分離し、非アクティブ会話をリネームしてもアクティブ会話を変更してはならない
- **FR-003**: FrontendはEnterキーで有効なタイトルを保存し、Escキーまたはフォーカスアウトで保存せずキャンセルしなければならない
- **FR-004**: FrontendはIME変換中のEnterキーを保存操作として扱ってはならない
- **FR-005**: Frontendはtrim後1文字以上100文字以下のタイトルだけをAPIへ送信しなければならない
- **FR-006**: 空または空白のみの入力でEnterキーが押された場合、FrontendはAPIを呼ばず、編集を終了して元タイトルを表示しなければならない
- **FR-007**: 100文字を超える入力はAPIへ送信せず、編集状態を維持してインラインエラーを表示しなければならない
- **FR-008**: Frontendは同時に複数の会話タイトルを編集状態にしてはならない
- **FR-009**: Frontendは保存中の重複リクエストを防がなければならない
- **FR-010**: 更新成功時、FrontendはレスポンスのConversationで該当するローカル状態を置き換えなければならない
- **FR-011**: アクティブ会話の更新成功時、サイドバーと会話ヘッダーのタイトルを同じ成功レスポンスから更新しなければならない
- **FR-012**: 更新失敗時、Frontendは編集状態と入力値を維持し、対象会話の近くにインラインエラーを表示しなければならない
- **FR-013**: Functionsは`PUT /api/conversations/{id}/title`でタイトル更新を受け付けなければならない
- **FR-014**: Functionsは入力タイトルの前後空白を除去し、1文字以上100文字以下であることを検証しなければならない
- **FR-015**: Functionsは認証済みユーザーが所有する会話だけを更新し、存在しない会話と他ユーザーの会話に同じ404を返さなければならない
- **FR-016**: FunctionsはCosmos DBと開発用in-memory storeの両方でタイトルを永続化しなければならない
- **FR-017**: タイトル更新はConversationの`updatedAt`を変更してはならず、会話一覧の並び順を変更してはならない
- **FR-018**: タイトル更新でConversationの`id`、`userId`、`model`、`createdAt`を変更してはならない
- **FR-019**: タイトル更新にConversationやCosmos DBコンテナーのスキーマ移行を要求してはならない

### API Contract

#### Request

```http
PUT /api/conversations/{id}/title
Content-Type: application/json

{
  "title": "プロジェクト計画"
}
```

- `title`は必須の文字列
- 前後空白を除去した後、1文字以上100文字以下
- 日本語、絵文字、既存会話と同じタイトルを許可

#### Success Response

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": "conversation-id",
  "userId": "authenticated-user-id",
  "title": "プロジェクト計画",
  "model": "kimi-k2.6",
  "createdAt": "2026-08-22T00:00:00.000Z",
  "updatedAt": "2026-08-22T00:00:00.000Z"
}
```

`updatedAt`はリネーム前の値を維持する。

#### Error Responses

| Status | Condition |
|---|---|
| 400 | JSON不正、`title`欠落、文字列以外、trim後が空、100文字超過 |
| 401 | 認証済みユーザー識別子を取得できない |
| 404 | 会話が存在しない、または別ユーザーが所有している |
| 503 | 必須設定のCosmos DBを利用できない |

### Key Entity

既存のConversation型を変更せず利用する。

```ts
interface Conversation {
  id: string;
  userId: string;
  title: string;
  model: string;
  createdAt: string;
  updatedAt: string;
}
```

## Success Criteria

### Measurable Outcomes

- **SC-001**: ユーザーはサイドバー内で会話タイトルを編集し、Enterキー1回で保存できる
- **SC-002**: 非アクティブ会話のリネーム中および保存後も、表示中の会話が切り替わらない
- **SC-003**: Esc、フォーカスアウト、空白のみのEnterでは更新APIが0回であり、元タイトルが維持される
- **SC-004**: IME変換確定のEnterで更新APIが呼ばれない
- **SC-005**: 100文字を超えるタイトルはFrontendとFunctionsの両方で拒否される
- **SC-006**: API失敗後も入力値が残り、同じ入力から再試行できる
- **SC-007**: リネーム成功後、再読み込みしても新タイトルが表示される
- **SC-008**: 他ユーザーの会話IDと存在しない会話IDのどちらも404となり、データが変更されない
- **SC-009**: リネーム前後で`updatedAt`と会話一覧順が変わらない
- **SC-010**: FunctionsとFrontendのbuild・unit/integration test・lintが成功する

## Out of Scope

- 会話タイトルの自動生成（P1-004）
- チャット本文や会話ヘッダーからのリネーム操作
- 複数会話の一括リネーム
- タイトルの変更履歴、Undo、監査ログ
- 会話一覧の検索、並び替え、ピン留め
- APIエラー全般のメッセージ設計統一（P2-003）
- 複数タブ間での即時同期（P2-002）
- ConversationまたはCosmos DBコンテナーのスキーマ変更

## Assumptions

- 現行本番バックエンドはAzure Functionsであり、旧Expressバックエンドは対象外とする
- 既存のConversation型には`title`があり、スキーマ移行なしで更新できる
- desktopとmobileは同じConversationListを利用し、同一の編集挙動を提供する
- 一覧のローカルConversationを成功レスポンスで置き換えることで、アクティブ会話ヘッダーにも新タイトルを反映できる
- リネームは会話内容の更新ではないため、`updatedAt`と一覧順を維持する
- 本機能固有の入力・APIエラーだけをインライン表示し、アプリ全体のエラーUX統一はP2-003で扱う
