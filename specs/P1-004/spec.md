# P1-004: 会話タイトルの自動生成 — Specification

**Status**: Draft
**Date**: 2026-08-23
**Backlog**: [P1-004](../000_backlog/items/P1-004-auto-title.md)

## Overview

会話のタイトルを AI（OpenCode Go）に要約させて自動生成する。現在、送信時に会話を自動生成した場合は最初のユーザーメッセージ先頭30文字がタイトルになる一方、「新規チャット」ボタンで作成した会話は `New Chat` のまま残る。AI 要約により、会話一覧の識別性を向上させる。

※ ユーザーストーリーの P2/P3 は機能内優先度であり、バックログ ID の P1 とは別軸。

## User Stories

### US1: 新規チャットからの AI タイトル生成（P2）

- **Given** 「新規チャット」ボタンで会話を作成しタイトルが `New Chat` の状態、
- **When** 最初のメッセージを送信する（AI 応答の完了は待たない）、
- **Then** 生成が成功した場合、会話タイトルが AI 生成の要約タイトルに置き換わる

### US2: 自動生成会話のタイトル改善（P3）

- **Given** メッセージ送信時に会話が自動作成され、タイトルがメッセージ先頭30文字切り出しになっている状態、
- **When** 同様に初回送信する、
- **Then** 切り出しタイトルから AI 生成タイトルへ置き換わる（生成失敗時は切り出しのまま・自動リトライはしない）

### US3: 手動リネームの尊重（P2）

- **Given** ユーザーが手動でリネームした会話、
- **When** その後メッセージを送信しても、
- **Then** AI タイトル生成は行われず、手動タイトルが維持される

## Scope

### In Scope

- Functions API `POST /api/conversations/{id}/title/auto` の新設（認証必須・所有者チェック・生成元テキストはリクエストボディで受ける）
- OpenCode Go を使ったタイトル生成（`opencodeGo.ts` に `generateTitle()` 追加。チャット本体とは独立した短命リクエスト）
- フロントエンドからの初回送信後トリガーとサイドバーへの反映
- 手動リネーム済み会話のスキップ

### Out of Scope

- タイトルの再生成 UI（明示的な「タイトル再生成」ボタン）
- 応答文ベースのタイトル生成（最初のユーザーメッセージのみを元にする）
- リネーム履歴の永続化（手動リネーム判定はフロントのセッション内 state で行う）
- タイトル生成モデルのユーザー選択
- 生成失敗時の自動リトライ

## Functional Requirements

- **FR-001**: `POST /api/conversations/{id}/title/auto` を実装しなければならない（認証必須）。会話が存在しない・他人のものの場合は 404
- **FR-002**: リクエストボディ `{ "text": "<最初のユーザーメッセージ本文>" }` を受け、`text` が空でない string でなければ 400 を返さなければならない（DB 上のメッセージ保存状況に依存しない。画像のみ送信ではフロントがAPIを呼ばない）
- **FR-003**: 生成にはチャット本体ストリームとは独立した短命リクエストを使わなければならない。実装は既存 `streamChat` で content チャンクを収集する方式とし（reasoning チャンクは使わない）、AbortSignal によるタイムアウト（20秒）を設けなければならない。モデルは `OPENCODE_GO_TITLE_MODEL` 環境変数（未設定時は `deepseek-v4-flash`）。モデルがカタログに存在しない場合も同モデルへフォールバックする
- **FR-004**: 生成結果のタイトルはサニタイズしなければならない。最初の非空行のみ採用し、前後空白と囲み引用符（`"`, `'`, `「」, "" 等）を除去、文字数はコードポイント基準（`Array.from(...).slice(0, 100).join('')`）で切り詰める。結果が空になった場合はフォールバックとして `Array.from(text).slice(0, 30).join('')` を使う
- **FR-003**: タイトル生成はチャット本体ストリームとは独立した短命リクエストで行い、クライアントへは最終テキストのみを返さなければならない（SSE をフロントに流さない）。実装は既存 `streamChat` で content チャンクを収集する方式とし（reasoning チャンクは使わない）、AbortSignal によるタイムアウト（20秒）を設けなければならない。モデルは `OPENCODE_GO_TITLE_MODEL` 環境変数（未設定時は `deepseek-v4-flash`）。モデルがカタログに存在しない場合は同モデルへフォールバックし、`console.warn` で設定ミスを検知可能にしなければならない
- **FR-006**: フロントエンドは初回メッセージ送信直後（AI 応答の完了を待たない）に本APIを fire-and-forget で呼び出さなければならない。会話IDには state の `activeConversationId` ではなく `create()` の戻り値 `conv.id` を使わなければならない。成功時は返却された Conversation で一覧を更新する
- **FR-007**: トリガー条件は「(a) この送信で会話を新規作成した、または (b) 現在のタイトルが定数 `NEW_CHAT_TITLE`（'New Chat'）と一致する」かつ「当該会話をこのセッション内で手動リネームしていない」こととしなければならない。`NEW_CHAT_TITLE` 定数はフロント内で一箇所に定義し使い回すこと
- **FR-008**: タイトル生成が失敗した場合、エラーを UI に出してはならず、チャット機能は継続しなければならない（コンソール警告のみ）
- **FR-009**: 生成に失敗してタイトルが `New Chat` のまま残った場合、次回送信時に条件 (b) により再試行され得る（自己修復。会話1件あたり成功するまで送信ごとに最大1回の LLM 呼び出しが発生し得る）

## Non-Functional Requirements

- **NFR-001**: タイトル生成はチャットのストリーミング応答をブロックしてはならない（送信処理とは独立に実行する）
- **NFR-002**: タイトル生成APIのタイムアウト/失敗時も会話・メッセージの保存に影響があってはならない
- **NFR-003**: タイトル生成は会話ごとに最大1回の LLM 呼び出しとし、デフォルトモデルは安価・高速な `deepseek-v4-flash` を使ってコスト・レイテンシを抑える

## Edge Cases

- **生成中にユーザーが手動リネーム**: 最終書き込み優先（競合制御は対象外）。フロントはトリガー時点の手動リネームフラグでのみ判定する
- **生成中に会話を削除**: API は 404 を返す。フロントは握りつぶす
- **OpenCode Go 障害・タイムアウト（20秒）**: FR-008 のとおり無言でフォールバック（切り出しタイトルのまま）
- **画像のみの送信**: テキストがないためフロントはAPIを呼び出さない
- **同時に複数タブで同一会話に送信**: last-write-wins（対象外）
- **手動リネーム先がたまたま `New Chat` の場合**: 条件 (b) は文字列一致判定のため次回初回相当送信で AI タイトルに上書きされ得る（許容）
- **マルチタブ・別デバイスでの手動リネーム**: フロントのセッション内フラグでは検知できないため、最終書き込み優先で上書きされ得る（対象外）

## API Contract

```
POST /api/conversations/{id}/title/auto
body: { "text": "<最初のユーザーメッセージ本文>" }
→ 200 更新後の Conversation オブジェクト単体（PUT /api/conversations/{id}/title と同形式）
→ 400 text 欠落・空 / 404 会話なし・他人の会話 / 401 未認証
→ 503 OpenCode Go 障害時（ただしフロントは握りつぶす）
```

## Acceptance Criteria

- **SC-001**: US1〜US3 のシナリオがすべて成立する
- **SC-002**: 生成 API 成功後、追加操作なしでサイドバーの一覧が更新される
- **SC-003**: タイトル生成APIが失敗・タイムアウトしても、メッセージ送信・ストリーミング表示は正常に動作する
- **SC-004**: 手動リネーム済みの会話ではタイトル生成APIが呼び出されない
- **SC-005**: 生成失敗時に自動リトライが発生しない
- **SC-006**: `npm run build` / `npm test`（frontend と functions 両方）、frontend `npm run lint` が成功し、今回差分に新規 lint 警告がない
