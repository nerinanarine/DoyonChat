# Feature Specification: ストリーミング中断時の中間保存

**Feature Branch**: `[feat/p1-003-p2-003-p2-013]`

**Created**: 2026-08-31

**Status**: Implemented（functions/frontend自動テスト完了、停止時部分保存・中断表示・二重保存防止を実装。Azure Functions host disconnect verification pending）

**Input**: [P1-003 backlog item](../000_backlog/items/P1-003-partial-save-on-stop.md)

> **対象範囲:** 本仕様の必須対象は、ユーザーが停止ボタンでストリーミングを中断した場合の中間保存である。ネットワーク切断やブラウザ終了時の自動復旧は別途扱う。

## User Scenarios & Testing

### User Story 1 - 生成途中の回答を保存する (Priority: P1)

ユーザーはAIの回答生成中に停止ボタンを押しても、その時点までに受信した回答と推論を失わず、会話履歴として確認できる。

**Why this priority**: 長い回答の生成を止めたい場合に、既に受信した内容まで失われるとデータ損失になるため。

**Independent Test**: ストリーミング中に複数の回答チャンクを受信させて停止操作を行い、画面上のストリーミング状態が終了し、保存APIまたは同等の永続化処理に中間内容が1件だけ保存されることを確認できる。

**Acceptance Scenarios**:

1. **Given** AI応答の本文または推論を受信中の状態、**When** ユーザーが停止ボタンを押す、**Then** 生成が中断され、受信済みの本文と推論を含むアシスタントメッセージが保存される
2. **Given** 停止処理が完了した状態、**When** ユーザーが画面を表示している、**Then** ストリーミング表示が終了し、保存された中間回答が通常のメッセージとして表示される
3. **Given** 中間回答が保存された状態、**When** ユーザーがページを再読み込みする、**Then** 停止時点までの本文と推論が会話履歴から復元される
4. **Given** 停止処理中の状態、**When** 停止操作が繰り返される、**Then** 保存や中断処理が重複実行されない

### User Story 2 - 受信前の停止を安全に扱う (Priority: P1)

ユーザーは回答をまだ1文字も受信していない状態でも停止でき、停止した事実が会話履歴から分かる。

**Independent Test**: ストリーム開始後に本文・推論チャンクを受信する前に停止し、アシスタントメッセージが1件だけ保存され、所定の中断表示が復元されることを確認できる。

**Acceptance Scenarios**:

1. **Given** ストリーミングが開始済みだが本文も推論も未受信の状態、**When** ユーザーが停止ボタンを押す、**Then** アシスタントメッセージが1件保存され、本文には`(生成が中断されました)`が記録される
2. **Given** 停止前にユーザーメッセージが保存済みの状態、**When** 中間保存が行われる、**Then** ユーザーメッセージが重複せず、アシスタントメッセージだけが追加される

### User Story 3 - 通常完了と所有権を維持する (Priority: P1)

停止機能を追加しても、通常完了したストリーミングの保存動作と、認証済みユーザーの会話所有権境界が変わらない。

**Independent Test**: 通常完了、停止、別ユーザーの会話に対する停止・保存をそれぞれテストし、通常完了は1件保存、停止は中間内容保存、他ユーザーの会話は変更不可となることを確認できる。

**Acceptance Scenarios**:

1. **Given** ストリームが最後まで正常完了した状態、**When** 完了処理が実行される、**Then** 既存どおり完全なアシスタントメッセージが1件だけ保存される
2. **Given** 認証済みユーザーが所有していない会話、**When** 中断保存を試みる、**Then** 会話やメッセージは変更されず、既存の認証・所有権エラー方針に従う

## Edge Cases

- 本文だけを受信して推論を受信していない場合は、本文を保存し、推論は省略する
- 推論だけを受信して本文を受信していない場合は、推論を保存し、本文は中断表示を含めて扱う
- 停止直前の最後のチャンクと停止通知が競合しても、受信済みチャンクを失わない
- 停止後に遅れて到着したチャンクは保存済みメッセージへ二重追加しない
- 空白だけを受信した場合は、空メッセージを保存せず中断表示を使用する
- 保存処理が失敗した場合は、ユーザーへエラーを通知し、同じ内容の重複保存を行わない
- 通常完了と停止完了の競合時は、アシスタントメッセージを二重保存しない

## Requirements

### Functional Requirements

- **FR-001**: ユーザーが停止ボタンを押したとき、進行中のストリーミングを中断できなければならない
- **FR-002**: 停止時点までに受信した本文をアシスタントメッセージとして保存しなければならない
- **FR-003**: 停止時点までに受信した推論を、既存のMessage形式に従って保存しなければならない
- **FR-004**: 本文と推論を一切受信していない停止では、`(生成が中断されました)`を本文として保存しなければならない
- **FR-005**: 停止による中間保存は、1回の停止操作に対して1回だけ実行されなければならない
- **FR-006**: 中間保存後、Frontendはストリーミング中状態を解除し、保存されたメッセージを表示しなければならない
- **FR-007**: ページ再読み込み後も、中断時点の本文・推論・中断表示を復元できなければならない
- **FR-008**: 停止処理はユーザーメッセージの重複保存を発生させてはならない
- **FR-009**: 通常完了時の既存保存動作を変更してはならず、停止と通常完了でアシスタントメッセージを二重保存してはならない
- **FR-010**: 中間保存でも既存の認証・会話所有権境界を維持しなければならない

### Data Requirements

- 保存するアシスタントメッセージは既存の`Message`型を使用する
- `conversationId`、`role: assistant`、`content`、`reasoning`（存在する場合）、`createdAt`を保持する
- 既存メッセージの内容や順序を変更せず、新しい中間アシスタントメッセージだけを追加する

## Success Criteria

### Measurable Outcomes

- **SC-001**: 回答チャンク受信後の停止で、受信済み本文が失われず1件のアシスタントメッセージとして復元される
- **SC-002**: 本文・推論の未受信状態で停止した場合、`(生成が中断されました)`が1件だけ保存・復元される
- **SC-003**: 停止操作の繰り返しや停止・完了競合で重複メッセージが発生しない
- **SC-004**: 停止後に通常の新規メッセージ送信を継続できる
- **SC-005**: FunctionsとFrontendのunit/integration test、buildが成功する

## Out of Scope

- ネットワーク切断やブラウザ終了時の自動的な中間保存
- 保存済み中間回答の編集・再生成・Undo
- ストリーミング停止以外のAPIエラーの文言設計（P2-003）
- ローディング表示のデザイン（P2-013）
- ConversationまたはMessageスキーマの大規模な変更

## Assumptions

- 現行バックエンドはAzure Functions、FrontendはReactである
- 既存の会話・メッセージ取得APIで保存済みメッセージを再読み込みできる
- 停止処理の具体的な通信方式（SSE切断、停止通知、専用APIなど）は実装計画で決定する
- ユーザーが停止を明示的に操作した場合だけを本仕様の成功条件とする
