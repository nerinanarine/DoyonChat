# P4-001: ローカルUI確認環境の計画

この計画は UI 改修そのものではなく、改修に先立ってローカルでUIを確認できる状態にするためのもの。UI改修の着手はヒアリング後。本計画(ローカル環境整備)はUI改修方針に依存せず実施可能。

## Phase 0: 環境確認

- [ ] frontend、functions、gateway、Azurite の既存構成と必要な環境設定を確認する。
- [ ] 必要ポート (`5173`、`7071`、`8787`) とサービス間の依存関係を整理する。
- [ ] 起動後に使うHTTP疎通先とブラウザで開くローカルURLを特定する。

**検証方法:** 環境確認後、各HTTP疎通先に `curl` を実行する対象と期待する応答を記録する。ブラウザで開くURLも記録する（このPhaseではサーバーを起動しない）。

## Phase 1: 起動手順確立

- [ ] frontend、functions、gateway、Azurite のローカル起動手順と停止手順を整理する。
- [ ] 必要な環境設定と、サービス間接続に必要な設定を明確にする。
- [ ] 起動順序と起動完了の判定方法を整理する。

**検証方法:** 起動後、frontend (`:5173`)、functions (`:7071`)、gateway (`:8787`) の確認先に `curl` を実行し、HTTP応答を確認する。ブラウザでfrontendのURLを開き、ページ表示を確認する。

## Phase 2: UI確認可能化

- [ ] 4コンポーネントを含むローカル環境で、frontendから必要なサービスへの疎通を確認する。
- [ ] ローカルUIの表示確認手順と確認結果を記録する。
- [ ] 上記の受け入れ条件を満たすことを確認する。

**検証方法:** frontend、functions、gateway のHTTP疎通先へ `curl` を実行し、Azurite (`http://127.0.0.1:10000` 等) へも curl/SDK で接続確認して、サービス間接続を確認する。ブラウザでローカルUIを開き、ページが表示されることを確認する。

## Phase外

UI改修自体はこの計画のPhase外であり、内容・対象範囲とも未定。実施前にヒアリングし、合意後に別途計画する。
