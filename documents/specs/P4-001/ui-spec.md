# 目的

スマートフォンからデスクトップまで、画面サイズに応じてチャット画面を使いやすく表示できるよう、レスポンシブ対応の要件を定める。

## 現状の問題点

- レイアウトの切り替えが `md` ブレークポイントに偏り、`sm`・`lg` 向けの調整がないため、中間サイズで適切な表示にならない場合がある（`AppLayout.tsx:57,76,107`）。
- 画面高を `h-screen` に固定しており、モバイルブラウザーの表示領域変化に追従できない（`AppLayout.tsx:55`、`App.tsx:268,275,283`）。
- サイドバー幅が `w-64` 固定で、狭い画面に適した幅の調整がない（`ConversationList.tsx:72`）。
- チャット本文の幅制限がなく広画面で行長が伸びる（`ChatMessage.tsx:23`、`ChatMessageList.tsx:73`）。
- Markdown のテーブルに横方向のオーバーフロー処理がなく、狭い画面でレイアウトを崩す可能性がある（`MarkdownRenderer.tsx:44`）。
- 削除・コピー操作が hover 表示に依存しており、タッチ端末では操作を見つけにくい（`ConversationList.tsx:143`、`CodeBlock.tsx:39`）。
- 入力処理に IME 変換中の Enter キーを送信扱いしないためのガードがない（`ChatInput.tsx:30-33`）。

## 要件

### レイアウト

- スマートフォンからデスクトップまで、利用可能な画面幅・高さに応じてチャット領域とサイドバーを表示する。
- ブレークポイントは Tailwind 既定値（`sm` 640px、`md` 768px、`lg` 1024px）を基準とし、`md` 未満をモバイル、`md` 以上をデスクトップとして扱う。
- モバイルブラウザーの表示領域の変化を考慮し、画面高は `100dvh` を基準にして `env(safe-area-inset-*)` でノッチ・ホームインジケーター領域を確保し、入力欄を含む画面が縦方向に利用できるようにする。
- チャット本文は読みやすい行幅を保ち、広い画面では本文の最大幅を 768px（`max-w-3xl` 相当）に制限して中央寄せする。
- 幅が狭い場合、Markdown のテーブルは必要に応じてテーブル領域内で横スクロールでき、ページ全体の横はみ出しを起こさない。

### ナビゲーション

- デスクトップではサイドバーとチャットを併用でき、モバイルでは限られた画面幅に適したナビゲーションを提供する。
- モバイルのサイドバーは、背景（オーバーレイ）のタップまたは Escape キーで閉じられるようにする。
- サイドバーの開閉や表示状態が、チャット本文と入力欄の利用を妨げない。

### 入力

- 入力欄は画面サイズにかかわらず見つけやすく、メッセージ入力・送信に利用できる。
- IME 変換中の Enter ではメッセージを送信せず、変換確定後の操作で送信できる。
- IME 変換中かどうかの判定（`isComposing` または `keyCode === 229`）は共通処理にまとめ、チャット入力欄と設定内の全テキスト入力欄（表示名、エージェントのモデル、サブエージェントのモデル等）で同じガードを使う（`SettingsMenu.tsx:129-130`、`171-172`、`195-196`）。既存ガード `ConversationList.tsx:110` も共通化対象に含める。

### タッチ

- 削除・コピーなどの主要操作は、hover できないタッチ端末でも視認・実行できる。
- 削除・コピーなど hover で表示する操作はポインター端末に限定し、タッチ端末では常時表示する。
- タッチ操作の対象は 44×44px 以上を確保して押しやすくし、隣接する操作を誤って選びにくい。

## 対象外

- 機能追加は行わない。
- デザイン刷新は行わず、既存のデザインと操作の意図を維持したレスポンシブ対応に限る。

## 受け入れ条件

- [ ] #1 ビューポート幅 375px と 1280px で目視確認し、ナビゲーション・本文・入力欄が重ならず、ページ全体に横スクロールが発生しない。1280px では本文の行幅が最大幅に制限されている。
- [ ] #2 実機のスマートフォン（幅 375px 相当）で、ブラウザーの表示領域が変化しても入力欄を含む画面を利用でき、`dvh` と safe-area が反映される。
- [ ] #3 実機のタッチ操作で、削除・コピーなどの主要操作を hover に頼らず見つけて実行でき、各操作のタップ領域が 44×44px 以上ある。
- [ ] #4 IME ガードの単体テストで、変換中（`isComposing === true`）の Enter がチャット送信・設定保存を起こさないことを確認する。
- [ ] #5 実機の日本語 IME で、変換中の Enter では送信・保存されず、変換確定後の Enter で送信・保存できることを確認する。
- [ ] #6 モバイルのサイドバーが、背景タップと Escape キーで閉じることを確認する。
- [ ] #7 幅 375px で 6 列の Markdown テーブルを表示し、ページ全体の横はみ出しなく、テーブル領域内の横スクロールで全列を閲覧できる。

補足: 実測時にメッセージ送信で503相当のエラーが1件発生（HTTP503は未確認）したが原因未確定であり、上記条件の判定には影響しない（別途調査）。
