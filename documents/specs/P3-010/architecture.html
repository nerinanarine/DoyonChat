01全体構成

フロントは変えず、バックエンドを「直結」と「エージェント」の二系に分岐する。エージェント実行は Functions と分離した常駐基盤（Container Apps）に隔離し、Functions は認証・プロキシ・SSE 中継に徹する。

03通常チャット経路（変更なし）

P3-010 はこの経路を壊さない。後方互換は SSE パーサの「未知フィールド無視」規約で担保する。

04エージェント経路

会話の agentMode が ON の送信だけがこちらへ分岐する。gateway は pi プロセスの所有者として起動・JSONL 読取・回収・同時実行上限を一手に担う。

05承認フロー

pi に確認ダイアログのビルトインは無い。自作の承認ゲート拡張が tool_call を購読し、レベル判定の上で ctx.ui.confirm を発火させる。confirm 専用設計。

レベル定義

  • auto — 確認なし（将来の信頼ツール用）
  • dangerous-only — 危険表（write/edit/bash/powershell 既定）のみ確認
  • always — 全ツール実行前に確認

安全弁

  • 承認待ちは実行予算外（タイマー停止、上限120秒で自動拒否）
  • 拒否・タイムアウト・切断時は中断保存＋再取得可能
  • 承認は実行所有者のみ（run→会話→所有者照合）

06永続化マップ

正本は既存 CosmosDB のみ。pi 側資産は最小限（短期＋エフェメラル）で、チャットUIに必要なのは最終回答テキストだけ。

資産場所寿命備考
会話・メッセージCosmosDB（既存）永続エージェント実行も通常メッセージとして保存
ユーザー設定CosmosDB（既存）永続agentApprovalLevel / agentModel / agentSubagentModel を追加
pi セッションsessions/{user}/{conv}.jsonl短期会話削除時は DELETE /sessions で破棄。再起動後は新規扱い
per-user pi 設定users/{user}/config/短期subagents.defaultModel 等。認証は置かない（サーバーenv供給）
実行レコードgateway メモリ（TTL 10分・最大200件）一時的再購読・最終回答回収用。events 上限2000件
作業ディレクトリエフェメラル実行単位コンテナ再起動で消去

07セキュリティ境界

境界の定義 実施済

  • pi にビルトインサンドボックスは無い → OS 境界（Container Apps）で隔離
  • ツール既定全無効（--no-tools）。有効化は allowlist 追加のみ
  • gateway は loopback 既定＋Entra JWT 必須（/health 除外）
  • Functions→gateway は MI トークン（静的キー経路は削除）
  • APIキー・上流本文はログ・SSE・UIに出さない（SafeErrorCode 契約）

残る前提条件 運用

  • replica=1 固定（セッション・レジストリのメモリ前提）
  • 初回起動時の per-user npm 展開 latency（ツール有効化時）
  • サブプロセスへのゲート伝播はツール有効化前に実機検証すること
  • プロンプトインジェクションの完全防止は不可（読ませる範囲制限で緩和）
