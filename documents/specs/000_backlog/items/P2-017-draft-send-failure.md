# P2-017: 新規作成失敗時の入力保持・エラー表示

## 概要

P2-015 Phase 4 横断レビューの残存リスクより切り出し。ドラフト状態（未選択）からの初回送信時、`POST /conversations`（`App.tsx` の `handleSend` 遅延パス内 `await create()`）が失敗すると例外が catch されず、`ChatInput` は fire-and-forget でテキストをクリア済みのため、エラー表示なく入力が消える。P2-015 以前からの既存挙動だが、遅延作成により新規チャットの主経路になるため露出が増える。

同根の問題として、ドラフト状態では `modelDisabledReason` が働かないため、カタログから消えたデフォルトモデルでも送信できて backend 400 → 同じくサイレント喪失となる。こちらも本項目で扱う。

## 受け入れ条件

1. 初回送信時の会話作成失敗でも入力テキストが保持される（消えない）
2. 作成失敗がユーザーに分かる形で表示され、再試行できる（P2-003 のエラー表示流儀に従う）
3. ドラフト状態で利用不可モデルが選ばれている場合は送信を停止し、再選択を促す
4. 既存会話の送信フローに退行がない

## スコープ境界

- P2-015 の残存リスク2・3の対処に限定する。送信中ローディング等の追加改善は含めない（必要なら別途起票）

## 関連ファイル（想定）

- `frontend/src/App.tsx`（`handleSend` 遅延パス）
- `frontend/src/components/Chat/ChatInput.tsx`
- `frontend/tests/unit/`
