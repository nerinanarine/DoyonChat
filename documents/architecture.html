システムアーキテクチャ — 全体像と接続点

Browser/PWA → Static Web Apps（frontend）→ Azure Functions（Flex）→ CosmosDB / OpenCode Go / agent gateway（Container Apps）→ pi + Azure Files。設定キーと主要ファイルの行番号を注記した簡潔な技術資料。

01全体構成

通常チャットは Functions から OpenCode Go へ直結。エージェント実行だけが Functions を経由して別基盤の gateway に分岐し、gateway が pi 子プロセスと Azure Files を所有する。認証・監視・シークレットは横断レイヤー。

05CI/CD（4 ジョブ）

deploy.yml は main push / 手動実行で、テスト → インフラ → Functions → フロントの順に直列実行する。

#ジョブ内容依存定義
1test-functionsnpm ci → build → test（COSMOSDB_REQUIRED=false）—.github/workflows/deploy.yml:31-48
2deploy-infraOIDC ログイン → Bicep デプロイ → outputs 取得1.github/workflows/deploy.yml:50-126
3deploy-functionsビルド・zip → Flex Consumption へデプロイ2.github/workflows/deploy.yml:128-166
4deploy-frontendVITE_* を注入してビルド → SWA へアップロード2, 3.github/workflows/deploy.yml:168-211

PR 用の ci.yml も 4 ジョブ: changes（paths-filter）→ test-functions / test-agent / validate-infra（Bicep build ＋ what-if）。

前提: gateway は ingress 公開のため、AGENT_AUTH_TENANT と AGENT_AUTH_AUDIENCE はデプロイ時に必須。AGENT_ENABLED=true のときは Functions 側も AUTH_ENABLED=true が必須。
AGENT_AUTH_*（デプロイ入力）と GATEWAY_AUTH_*（gateway 実行時 env）は別物。

06補足

  • 開発時のポート: フロント :5173 / Functions :7071 / gateway :8787。
  • フロントは gateway を直接呼ばず、必ず Functions の /api/agent/* を経由する（トークンと kill switch の一元化）。
  • gateway は minReplicas=0 / maxReplicas=1。コールドスタートは agent-starting として UI に通知される。
  • pi のツールは既定で全無効（--no-tools）。有効化は agent/tools.allowlist.json への追記のみ。
  • 仕様・計画資料は documents/specs/ 配下へ移動済み。
